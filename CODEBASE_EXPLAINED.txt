                         1. PROJECT OVERVIEW
================================================================================

IDLink is an ID processing and management system for MSU-IIT (Mindanao
State University - Iligan Institute of Technology).

PURPOSE:
- Students/Employees can apply for new IDs
- Users can revalidate expired IDs
- Staff can review, approve, or reject applications
- Track application status in real-time

USERS:
- Students: Apply for ID, track status, revalidate
- Employees: Same as students + contract monitoring
- Staff (ICTC): Review applications, manage records, send notifications

                         3. CORE CONCEPTS EXPLAINED
================================================================================

CONCEPT 1: COMPONENTS
A component is a piece of UI (like a button, card, or page) written as a
function that returns JSX (looks like HTML).

Example:
    function Button() {
      return <button className="bg-primary">Click Me</button>;
    }

CONCEPT 2: JSX
JSX is a syntax extension that lets you write HTML-like code in JavaScript.
It looks like HTML but you can use JavaScript variables and logic inside.

Example:
    const name = "Juan";
    return <p>Hello, {name}!</p>;  // {name} is JavaScript

CONCEPT 3: PROPS
Props are inputs you pass to a component (like function parameters).

Example:
    function Greeting({ name, role }) {
      return <p>Welcome, {name}! You are a {role}.</p>;
    }

    // Usage:
    <Greeting name="Juan" role="student" />

CONCEPT 4: STATE
State is data that changes over time in a component.
When state changes, the component re-renders (updates on screen).

Example:
    const [count, setCount] = useState(0);

    <button onClick={() => setCount(count + 1)}>
      Clicked {count} times
    </button>

CONCEPT 5: HOOKS
Hooks are special functions that let you use React features.
- useState: Manage changing data
- useEffect: Do something after render
- useNavigate: Navigate to other pages

================================================================================
                    4. HOW THE APP STARTS (ENTRY POINT)
================================================================================

FILE: main.tsx

This is the VERY FIRST file that runs when someone visits your app.

CODE:
    import { createRoot } from "react-dom/client";
    import App from "./App.tsx";
    import "./index.css";

    createRoot(document.getElementById("root")!).render(<App />);

WHAT HAPPENS:
1. Browser loads the page
2. Finds <div id="root"> in index.html
3. React creates a "root" and renders <App /> inside it
4. App component loads with all routes and providers

Think of it like:
    index.html = <div id="root"> is the empty container
    main.tsx   = says "Put <App> inside that container"
    App.tsx    = <App> is the full application

================================================================================
                         5. APP.TSX - THE BRAIN
================================================================================

FILE: App.tsx

This is the ROOT COMPONENT. It sets up the entire application.

PROVIDERS (Tools that work across the entire app):

1. QueryClientProvider
   - Purpose: Manages data fetching and caching
   - Why: Instead of writing fetch logic everywhere, use React Query hooks
   - Alternative without it: useEffect + useState for every API call

2. TooltipProvider
   - Purpose: Enables tooltip components (hover info boxes)
   - Usage: Any component using Tooltip from shadcn/ui

3. Toaster & Sonner
   - Purpose: Shows toast notifications (success/error popups)
   - Usage: toast.success("Logged in!") in any component

4. BrowserRouter
   - Purpose: Enables URL-based navigation without page reloads
   - Alternative: Traditional <a href="/page"> which reloads the page

STRUCTURE:
    <QueryClientProvider>
      <TooltipProvider>
        <Toaster />
        <Sonner />
        <BrowserRouter>
          <Routes>
            {/* All your page routes here */}
          </Routes>
        </BrowserRouter>
      </TooltipProvider>
    </QueryClientProvider>

================================================================================
                        6. ROUTING EXPLAINED
================================================================================

HOW IT WORKS:
BrowserRouter watches the URL and shows the matching Route's component.

CODE:
    <Routes>
      <Route path="/" element={<Landing />} />
      <Route path="/login" element={<Login />} />
      <Route path="/student/dashboard" element={<StudentDashboard />} />
    </Routes>

PATH MATCHING:
    "/"            → Landing.tsx
    "/login"       → Login.tsx
    "/anything"    → NotFound.tsx (the "*" catches all)

ROUTE GROUPING:
Routes are grouped by user role for clarity:
    {/* Student Routes */}
    <Route path="/student/dashboard" element={<StudentDashboard />} />

    {/* Employee Routes */}
    <Route path="/employee/dashboard" element={<EmployeeDashboard />} />

    {/* Staff Routes */}
    <Route path="/staff/dashboard" element={<StaffDashboard />} />
    <Route path="/staff/records" element={<RecordsManagement />} />

WHY GROUP?
Makes it easier to see what each user type can access.

DARK MODE
------------------------------------------------------------------------------

Toggle via: Adding/removing "dark" class on <html> element

When .dark is present, all CSS variables are remapped to darker versions:
  --background becomes hsl(220 13% 12%)  # Dark charcoal
  --foreground becomes hsl(210 16% 95%) # Light gray

Navbar.tsx handles this toggle with:
  document.documentElement.classList.add("dark")
  document.documentElement.classList.remove("dark")

                      10. API INTEGRATION PATTERN
================================================================================

CURRENT APPROACH: Fetch to local backend

All API calls follow this pattern:

LOGIN (POST):
  const res = await fetch("http://localhost:5000/api/login", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ email, password })
  });

  const data = await res.json();

  if (res.ok) {
    // Success
    localStorage.setItem("user", JSON.stringify(data));
    navigate("/dashboard");
  } else {
    // Error
    toast.error(data.message);
  }

REGISTER (POST):
  Similar to login but with more fields (idno, fullname, course, year, role)

GET APPLICATIONS:
  const res = await fetch("http://localhost:5000/api/applications?user=" + idno);
  const data = await res.json();
  setApplications(data);

UPDATE STATUS (PUT):
  const res = await fetch(`http://localhost:5000/api/applications/${id}`, {
    method: "PUT",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ status: "approved", notify: true })
  });

DELETE (DELETE):
  const res = await fetch(`http://localhost:5000/api/applications/${id}`, {
    method: "DELETE"
  });

                      11. STATE MANAGEMENT
================================================================================

LOCAL STATE (useState):
Used for component-specific data that doesn't need to be shared.

  const [email, setEmail] = useState("");
  const [loading, setLoading] = useState(false);
  const [user, setUser] = useState<User | null>(null);

LOCAL STORAGE:
Used for persistence across page reloads.

  // Save
  localStorage.setItem("user", JSON.stringify(userData));

  // Load
  const stored = localStorage.getItem("user");
  if (stored) setUser(JSON.parse(stored));

  // Remove
  localStorage.removeItem("user");

EFFECT CLEANUP:
When setting up intervals or subscriptions, always clean up.

  useEffect(() => {
    const interval = setInterval(() => fetchData(), 5000);

    return () => clearInterval(interval);  // This runs on unmount
  }, []);

  useEffect(() => {

                      13. SUPABASE MIGRATION NOTES
================================================================================

Based on REDESIGN_MAP.md, here's how to migrate:

AUTHENTICATION:

BEFORE (Current):
  fetch("http://localhost:5000/api/login", {
    method: "POST",
    body: JSON.stringify({ email, password })
  })

AFTER (Supabase):
  supabase.auth.signInWithPassword({ email, password })

BEFORE:
  fetch("http://localhost:5000/api/register", {
    method: "POST",
    body: JSON.stringify({ email, password, fullname, role })
  })

AFTER:
  supabase.auth.signUp({
    email,
    password,
    options: {
      data: { fullname, role }
    }
  })

APPLICATIONS:

BEFORE:
  fetch("http://localhost:5000/api/applications", {
    method: "POST",
    body: formData  // FormData for file uploads
  })

AFTER:
  supabase.storage.upload('photos', file)  // Upload files first
  supabase.from('applications').insert({
    photo_url: uploadedUrl,
    // ... other fields
  })

STEPS TO MIGRATE:
1. Create AuthContext to wrap app with supabase.auth.onAuthStateChange()
2. Define TypeScript types for User, Application, Contract, TeamMember
3. Replace Login.tsx fetch with supabase.auth.signInWithPassword()
4. Replace Register.tsx fetch with supabase.auth.signUp()
5. Replace application queries with supabase.from('applications').select()
6. Set up Row Level Security (RLS) policies in Supabase dashboard
